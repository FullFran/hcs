# HCS v0.1.0-draft.12

Specification and SDK release. Instance documents keep `"hcsVersion": "0.1"`. It adds what a host
needs to stop carrying its own copies of the HCS-0007 acceptance rule and signed sync, and closes
the gap between engine-built MCP tool names and the declarations they come from (#111, #113).

<!-- release:artefact -->

## Changes a host must make

- **Hosts that project `mcp-server` entries:**
  - Look up a tool's declaration by the server entry that listed it and the name that server reports (HCS-0009-R007), never by parsing the engine-built name.
  - Re-apply declarations on every `tools/list`, including after `notifications/tools/list_changed` (R008). Withhold a tool a later list would give an engine name already in use (R010).
  - Report tool-name collisions at projection: `ambiguous_provider` between entries, `unsupported_contribution` against a host tool or within one entry (HCS-0008-R040). Under `all-or-nothing`, an entry-entry collision fails the generation.
  - `sdk.buildToolNameMap` computes the map and the report for a naming rule.
- **Hosts and publishers with their own sequence or key-set version checks:** they can replace them with `signing.checkEnvelopeSequence`, `signing.checkKeySetVersion` and `signing.nextSequence`. The rule is unchanged.
- **Consumers verifying a download:** take the tarball sha256 from the release page (the `.sha256` asset or the table below), not from `docs/releases/` (#117).

## What changed

### Artefact

- The release job pins Node 24.14.1 (and its npm). The release body names the Node and npm versions that packed the SDK tarball, so it can be rebuilt byte for byte (#118).
- The release notes in `docs/releases/` hold prose only. The workflow writes the digests into the release body (#109).
- The README and the consumer kit say where to take the digest from (#117).

### Specification and conformance

- **HCS-0009:**
  - New R007: tool identity is (server entry, reported tool name).
  - New R008: declarations apply to every tool list.
  - New R009: SHOULD report undeclared names.
  - New R010: a later list that reuses an engine name is withheld.
  - OQ-0009-3 is closed.
- **HCS-0008:**
  - New R040: projected tool-name collisions.
  - Appendix A.1 records each engine's MCP tool naming rule and how far each rule is verified.
- **HCS-0006:** the `unsupported_contribution` row covers the R040 cases.
- **ADR-0040 (Proposed):** tool identity and list drift. It rejects "first in order wins" because that rule depends on order and contradicts R006.
- **Counts:** 533 cases (518 in draft.11) and 164 requirements (159). All new cases are `host` level.

### SDK

- Version 0.1.0-draft.12.
- **`signing`:** `checkEnvelopeSequence`, `checkKeySetVersion` and `nextSequence` (with `SigningRejection`) are the HCS-0007 acceptance rule as pure functions. `verifyEnvelope` and `verifyKeySet` use them with no behaviour change (#124).
- **`sync` (experimental):**
  - `syncSigned` reads the accepted state for a scope, verifies only through `verifySignedCatalog`, records the accepted state after verification (HCS-0007-R015), then applies.
  - It holds the host lock for the whole call.
  - `fileAcceptedStateStore` writes atomically and fails closed on an unreadable state (#66).
- **`buildToolNameMap` and `engineToolName`** compute the tool-name map and the R040 report for the `opencode`, `pi` and `mcp-double-underscore` rules, or a custom one.
- **Windows:** the SDK now runs there, covering key files, projection paths and file modes (#108). CI runs on Linux, Windows and macOS (#107).
- The SDK still requires Node 24 or later.
