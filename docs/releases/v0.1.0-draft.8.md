# HCS v0.1.0-draft.8

Specification and SDK release. Instance documents keep `"hcsVersion": "0.1"`.

This draft writes down five patterns that at least two of the consuming harnesses (HagaHarness,
RE;write, training-mcp) had already built on their own: effect classes for package tools,
proposals that only a person answers, HCS errors inside MCP tool results, client limits for
projection, and the tooling a consumer uses to pin a release and measure itself. Almost all of
it is additive; see "Changes a host must make" for the two places an existing host is affected.

## Changes a host must make

- **Tools of package MCP servers are presented by effect class** (new HCS-0009-R003 to R005,
  #91). A host that shows the tools of an `mcp-server` contribution to an engine, a client or a
  person presents each tool's MCP annotations from the effect class the package declares,
  presents a tool with no usable declaration with the MCP defaults (destructive, open world),
  and discards the annotations the server reports about itself.
- **New error code `proposal_conflict`** (HCS-0006, #92). The closed code set has 19 codes; a
  client that validates codes against the set must accept it.

## What changed

### Specification

- **HCS-0009 tool surface** (new, ADR 0034, #91). Effect classes `read`, `additive` and
  `destructive`, with optional `idempotent` and `openWorld` flags, declared per tool in the
  contribution's `server.json` under `_meta["io.github.fullfran.hcs"].tools` (R001); a mapping
  to the MCP annotation hints (R003); fail closed (R004); the host's annotations, not the
  server's (R005); a class is never a grant (R006, HCS-0005-R002). HCS-0008 section 6.4 points
  at it. Open: OQ-0009-1, finer kinds only one harness uses.
- **HCS-0010 proposals** (new, ADR 0036, #92). The record an agent write becomes: nothing is
  applied unless `accepted` (R002); one transition from `pending` (R003); only a person, or a
  grant or denial the host holds, answers (R004, HCS-0005-R015); the answer names its HCS-0005
  decision record (R005); a proposal whose `base` no longer matches its target is refused
  (R006); an undo is a new record and is refused when not allowed (R007, R008); answered
  records are never edited (R009); a retry returns the existing proposal and a reused identity
  with other content is refused, mechanism open (R010, R011); an action type is an HCS-0005
  permission id (R012). Open questions OQ-0010-2 to OQ-0010-8.
- **HCS-0005**: OQ-0005-1 narrowed. HCS-0010 settles how tools are grouped (an action type is a
  permission id); HCS still defines no permission ids.
- **HCS-0006 errors in MCP tool results** (new section 4.5, R007 to R009, ADR 0035, #89).
  `isError: true`, the error object at `structuredContent.hcsError`, a `text` item in
  `content` (R007); the error result validates against the tool's `outputSchema` (R008); when a
  client reads an HCS error from a tool result (R009). R006's list of sources gains R009. Which
  transport to use is guidance, not a requirement; a host that sends every HCS error as a
  JSON-RPC error still conforms. Open: OQ-0006-5, an agent recovery hint.
- **HCS-0006 code `proposal_conflict`** (#92), for refusals under HCS-0010 R003, R006, R008
  and R011.
- **HCS-0008 client limits** (new section 6.9, R036 to R039, ADR 0037, #90). A host declares a
  client's limits (schema `urn:hcs:schema:hcs-0008:client-limits:0.1`, no default in HCS);
  a server over the declared `toolListBytes`, or with no measurement when a budget is declared,
  is `unsupported_contribution` (R037, R038); server instructions SHOULD be useful within the
  declared prefix (R039). The 512-character figure in ADR 0037 is OpenAI Apps SDK guidance.
- **ADR 0038, Proposed**: two harnesses drive their engines over line-delimited JSON on stdio
  instead of ACP. Section 6.8 is unchanged; OQ-0008-8 and OQ-0008-9.

### Conformance

- Cases for HCS-0009, HCS-0010, HCS-0006-R007 to R009 and HCS-0008-R036 to R038. The `client`
  level reads a `tools/call` response from `input.response`; projection cases take
  `clientLimits` and a contribution's `toolListBytes`.
- 508 cases in total (408 in draft.7): 385 run by the reference runner, 123 at `host` level.
  153 requirements (128 in draft.7). HCS-0006-R007 to R009 and the new specs are in no profile
  yet.
- **Consumer kit** (`tools/consumer-kit/`, non-normative, #88): `hcs_kit.py sync` vendors a
  release checked against your pinned sha256 and its `SHA256SUMS` and writes `PIN.json`;
  `verify` re-checks the vendored tree; `baseline` and `compare` read the runner's `--report`
  and fail only on regression, with a `divergences.json` for deliberate divergences and
  not-applicable requirements. See `docs/adoption.md`. The kit is in the repository, not in the
  release artefact.

### SDK

- `toToolResult`, `fromToolResult` and `withHcsErrorOutput` (HCS-0006 section 4.5).
- `tool-effects`: `annotationsFor`, `classifyTools`, `checkToolEffects` and
  `checkServerToolEffects` (HCS-0009), with `EFFECT_CLASSES` and `FAIL_CLOSED_ANNOTATIONS`.
- `proposals`: `readProposal`, `submitProposal`, `answerProposal`, `proposeUndo`,
  `digestPayload`. Refusals are a `ProposalRefusal` with a `reason`.
- `proposal_conflict` in `HCS_ERROR_CODES`, HTTP status 409.
- The SDK still requires Node 24 or later.
