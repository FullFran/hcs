# HCS v0.1.0-draft.3

Third pre-release of HCS 0.1. Every document is still Draft and no host passes
a profile yet. Instance documents keep `"hcsVersion": "0.1"`: every instance
valid under draft.2 is still valid (checked against all 25 valid draft.2
document cases), as HCS-0000 section 5 requires within one minor. See "How to
pin HCS" in the README.

## Upgrading from draft.2

- **`index.json` gains members (same `indexFormat`).** Each requirement carries
  `profiles` and `cases`, and a top-level `unprofiled` list names the 50
  requirements that have cases but no profile (#43). A host that selects cases
  by profile should also track `unprofiled`; those requirements are part of no
  conformance claim.
- **Projection case inputs gain members.** A contribution with a
  `registryType: "file"` package lists its `files`, and a case may give
  `hostRuntimes` (`{runtimeHint: [control variable names]}`). A harness that
  feeds projection cases to its own adapter must pass them through.
- **New schema** `urn:hcs:schema:hcs-0008:acp:0.1` and **new error code**
  `generation_mismatch`. A client implementing draft.2 reads that code as "no
  HCS error" (HCS-0006 section 4.3).
- **Stricter host requirement: HCS-0008-R019.** A host that declares a guard on
  model requests now needs network confinement. Keeping provider keys out of the
  run is a second layer and no longer enough on its own (ADR-0028).
- No instance document changes shape or meaning.

## Changes

### Release tooling (#43)

- `index.json`: per-requirement `profiles` and `cases`, plus `unprofiled`. No
  profile is widened or created. A requirement joins a profile when a host can
  pass all its cases.

### HCS-0000 Conventions (#30)

- Section 7 names HCS's own namespace for protocols that ask for reverse-DNS
  extension names, `io.github.fullfran.hcs`. Like the `urn:hcs:` schema ids, it
  is provisional.

### HCS-0006 Typed errors (#30)

- New registry code `generation_mismatch`.
- The `unsupported_contribution` row covers bundled MCP servers that cannot be
  started as declared.

### HCS-0008 Host adapter

- **Section 6.4.1, MCP server code inside the generation (#28; ADR-0026):**
  `registryType: "file"`.
  - R021: a relative `identifier` inside the contribution folder, `stdio` only.
  - R022: the server runs from the immutable generation.
  - R023: the host provides the runtime; runtime arguments and control
    variables such as `NODE_OPTIONS` are refused.
  - R024: secrets only through the environment.
  - Errors are reported in a fixed order.
  - OQ-0008-7: whether registry packages may be projected at all.
- **R030, MCP values delivered literally (#45; ADR-0028):** the `server.json`
  substitutions are applied once. The adapter then escapes each value for the
  engine, or reports `unsupported_contribution`. Appendix A records what each
  engine interprets.
- **Section 6.6, R019 rewritten (#46; ADR-0028):** no request of the run can
  leave toward a model provider except through the guard, which runs outside
  the run's processes. Network confinement meets it; credential confinement
  alone does not.
- **Section 6.7, R025, no ambient configuration (#30; ADR-0027):** a run reads
  nothing from user-global locations, and from the workspace only instruction
  files the host allows.
- **Section 6.8, projection over ACP (#30; ADR-0027):** an extension under
  `io.github.fullfran.hcs`.
  - R026: capability negotiation.
  - R027: generation id and skill paths in `session/new`.
  - R028: `session/load` and `session/resume` on another generation are refused
    with `generation_mismatch`.
  - R029: a `loaded` report used for health.
- Section 2: a projection may be the parameters of the request that creates an
  engine session.
