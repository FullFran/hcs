# HCS v0.1.0-draft.2

Second pre-release of HCS 0.1. Every document is still Draft and no host passes
a profile yet. Instance documents keep `"hcsVersion": "0.1"`: every instance
valid under draft.1 is still valid (HCS-0000 section 5 now makes that the rule
within one minor). See "How to pin HCS" in the README.

## Upgrading from draft.1

- **Breaks a runner or test harness pinned to draft.1:** the case schema adds the
  `client` level and `expect.hcsError`. A draft.1 runner reports the 7 `client`
  cases as malformed. A harness that switches on `level` must handle or skip
  `client`.
- **Does not break instances:** catalogs, envelopes, key sets, errors and request
  documents valid under draft.1 stay valid (checked against every valid
  draft.1 document case).
- **Changes a host's behaviour if it implements HCS-0005:** a check is now also
  denied by a matching stored denial, and a grant with a `session` only matches
  checks from that session. Grants without `session` behave as before.

## Changes

### HCS-0000 Conventions

- Section 5: within one `0.MINOR`, drafts change instance schemas only
  additively; a breaking or reinterpreting change moves to the next MINOR and
  `hcsVersion`.

### HCS-0005 Authority (#35, #36, #31; ADR-0023, ADR-0024, ADR-0025)

- R005-R009, answers from a person:
  - ACP `allow_once`/`reject_once` decide one operation and are never stored.
  - `allow_always` becomes a host-held grant limited to its session, with an
    `origin`.
  - `reject_always` becomes a stored denial that wins over grants.
  - The engine or client never keeps a remembered answer the host cannot revoke.
  - R001 now names the one-operation answer.
- R010-R013, decision records:
  - One record per decision acted on and per grant or denial removed, never with
    the operation's content.
  - An unrecorded decision is a deny.
  - Records sent to a distribution SHOULD be CloudEvents.
- R014-R015:
  - Only an explicit allow before the deadline runs an operation; reject, timeout,
    ACP `cancelled`, a handler error or a lost client deny.
  - Answers come only through the host's channel to the person.
- Schema (additive):
  - `grant` and `check` gain optional `id`, `session` and `origin`.
  - New `denial` and `decisionRecord`.
  - `evaluationInput.denials`.

### HCS-0006 Typed errors (#32)

- R006: a client takes the HCS error only from `error.data.hcsError` or the
  problem's `hcsError`, never from top-level members. Problem members of the
  wrong type are ignored (RFC 9457 section 3.1).

### HCS-0008 Host adapter (#29; ADR-0025)

- Section 6.6, R019-R020: a guard on model requests sits on the model transport,
  so it covers the engine's own requests (compaction, summaries), and lets
  nothing through when it fails.

### Conformance

- 259 cases (was 215):
  - document 75
  - integrity 3
  - resolution 33
  - authority 14
  - distribution 37
  - projection 23
  - client 7
  - host 67
- The reference runner executes the 192 non-host cases (all pass) and reports 67
  host cases `pending` (#20).
- New `client` level, with fixtures a client's test suite can reuse instead of
  hand-written fakes.
- The reference evaluator applies stored denials and session limits.
- Profiles unchanged: CORE-0 (38 requirements), DISTRO-1 (22). The new HCS-0005,
  HCS-0006 and HCS-0008 requirements are not in a profile yet.
