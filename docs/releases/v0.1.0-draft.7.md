# HCS v0.1.0-draft.7

Specification and SDK release. Instance documents keep `"hcsVersion": "0.1"`.

This draft makes verification stricter in three places, each decided from what a second
independent implementation reported. A host that accepted the documents below under draft.6
must now refuse them; see "Changes a host must make".

## Changes a host must make

- **Number spelling** (HCS-0007-R004, #84). In an envelope or key set, a number token must match
  `-?(0|[1-9][0-9]*)`. `1.0`, `1e2`, `100e-2` and `-0` are `manifest_invalid`, whatever their
  value. A host that accepted and canonicalised those spellings now refuses them.
- **Repeated `keyid` in `signatures`** (new HCS-0007-R022, #84). Two signatures with the same
  `keyid` make the document `manifest_invalid`, before any signature is verified. A host that
  tried only the first, or any, signature of a `keyid` now refuses the document.
- **Key set of another `hcsVersion`** (HCS-0007-R002, #84) reports `unsupported_hcs_version`,
  not `manifest_invalid`.
- **Unsafe package archives** (new HCS-0001-R019 to R023, #83) report the new code
  `package_invalid`. A host that reported `integrity_mismatch` for an unsafe member, or an
  untyped error for a malformed tar or an exceeded unpack limit, changes to `package_invalid`.
  A caller that branched on `integrity_mismatch` for these must also handle the new code.

## What changed

### Specification

- **Order of the HCS-0007 checks** (section 5.2, ADR 0032, #84). (1) The document is readable:
  valid UTF-8 and JSON, no duplicated member name, no unpaired surrogate; otherwise
  `manifest_invalid` (R003). (2) `hcsVersion`: another version is `unsupported_hcs_version`
  even when the document also breaks a later rule. (3) The number rule R004, then the shape,
  the unique key `keyid` of R002, R022 and R023.
- **Bounds on keys and signatures** (new HCS-0007-R023, #84). A host MAY bound them; exceeding a
  bound is `manifest_invalid`, reported before any verification. HCS states no number.
- **Archive member safety** (HCS-0001-R019 to R023, ADR 0033, #83). OQ-0001-6 is closed. A host
  refuses a member with an empty, absolute, `..`, NUL or backslash path or a `.wh.` component
  (R019); any member that is not a regular file or a directory, and a directory that carries
  data (R020); a path equal to an earlier member's or below a regular file (R021). The checks
  run after `size`, `contentHash` and `contentId` and before any write (R022). A tar that
  cannot be parsed, or that exceeds a host limit, is refused (R023). HCS-0001-R018 is unchanged.
- **New error code `package_invalid`** (HCS-0006, #83).
- **Note for publishers.** A `./` root member, as GNU `tar -C dir .` writes, is an empty path
  under R019, and pax or GNU extended header records fall under R020. List members by name and
  use the ustar format.
- **I-JSON numbers bind extension members; how to retire distribution error codes** (#75, text
  only).
- New open question OQ-0007-7: small-order Ed25519 public keys.
- **Standards notes** (#81): A2A task state names, in-toto release against Statement version, a
  new note on OTLP, what the pinned OpenTelemetry GenAI conventions do and do not define, and
  where Agent Skills and Kubernetes probes are silent or out of the pin.

### Conformance

- **System under test interface** (#82). `python3 conformance/runner/run.py --sut COMMAND
  [ARG...]` runs the cases against an external command: one process per case, the case as JSON
  on stdin, one JSON result on stdout, protocol version equal to the case schema version. A
  system answers `ok`, `not-implemented` or `not-applicable`; `host` level cases stay pending.
  See "System under test" in `conformance/README.md`, `conformance/runner/reference_sut.py`
  and `conformance/examples/minimal-sut.mjs`.
- **Textual case inputs** (#84). A case may carry its document as exact bytes in
  `documentBase64`, so number spelling, duplicated member names and unpaired surrogates can be
  exercised. Existing cases are unchanged.
- **Integrity cases with `unpack`** (#83): `input.unpack`, `maxMembers` and `maxUnpackedBytes`.
- 408 cases in total (338 in draft.6): 314 run by the reference runner, 94 at `host` level.

### SDK

- **Behavior change: strict number spelling and repeated `keyid`** (#84). `signing.verifyEnvelope`
  and `signing.verifyKeySet` refuse a repeated `keyid`; with one `keyid` signed twice,
  `[valid, invalid]` was accepted before. New `signing.readEnvelope` and `signing.readKeySet`
  apply the order of section 5.2 to received text. The verify functions accept an optional
  `limits: {maxKeys, maxSignatures}`.
- **Behavior change: `sign-catalog` and `sign-keys`** refuse an input file that spells a number
  as `1.0`, naming HCS-0007-R004 and the offset (#84).
- **Behavior change: `package_invalid`** (#83). `unpackPackage` and `packageRequests` report it
  for unsafe members, a malformed tar and exceeded limits; `packageRequests` now runs the member
  checks, so a hostile archive is refused at authorization too.
- **`integrity_mismatch` says which transport check failed** and the observed digest, in
  `details` (#78).
- **`generation_mismatch`** is now in `HCS_ERROR_CODES` (#85); the spec and schema already had it.
- Error messages for a duplicated member and for a parse failure no longer include text of the
  document.
- The SDK still requires Node 24 or later.
