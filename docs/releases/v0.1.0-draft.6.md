## What changed

### Specification

- **`contentId` over the uncompressed package tar** (HCS-0001, #67). Catalog entries may carry
  a digest of the uncompressed tar, checked after `contentHash`.
- **Crash-safe generation switch** (HCS-0008 section 7.1, R031 to R035, ADR 0031, #72). A host
  persists the pending and return-to generations before it moves the active pointer, handles
  restarts from those records, keeps failure marks across restarts, and records a stop so a
  restart cannot loop; the stop ends with a new desired set or an operator action. OQ-0004-4
  is closed for generations; per-entry state stays open. New `recovery` conformance level.

### SDK

- **Behavior change: `fetchPackageBytes` verifies what it returns** (#70). It now throws
  `HcsFailure` `integrity_mismatch` (HCS-0001-R007) when a download is longer or shorter than
  `size` or its digest differs. Before, a short download was returned and an over-size one threw
  a plain `Error`. Hits in the content-addressed store are verified as well, and a bad store file
  is reported, not replaced from the network. New streaming helpers: `verifyBlobStream`,
  `collectVerifiedBlob`, `verifyingTransform`.
- **Publisher CLI** (#71). `npx hcs-sdk keygen | sign-keys | sign-catalog | pack`. Key files are
  PKCS#8 PEM created with mode 0600; existing outputs are never overwritten without `--force`;
  files that must hold public keys are refused when they contain private key material.
- **Host recovery** (#72): `readHostFacts`, `planRecovery`, `recoverHostState`,
  `cleanupGenerations`, `clearStop`; `applyDesiredSet` writes `generation-records.json`. State
  written by earlier drafts still loads.
- **Generation numbers are never reused** after cleanup (#68).
- **MCP `server.json` checks** for HCS-0008-R010 and R011 (#69).
- The SDK still requires Node 24 or later.
